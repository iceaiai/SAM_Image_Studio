Detection and segmentation across SAM families#

Detection answers “where?”; segmentation answers “which pixels?”#

A detector proposes target locations, often boxes and scores. A segmenter predicts a pixel mask from image features and prompts. SAM Image Studio combines these differently for each family; the presence of a text box does not make every underlying SAM version a native text detector.

SAM1: object prompts, grid candidates, and retrieval#

For one object, a point or area-derived box prompts the native predictor. The model returns a mask and quality score. It does not directly understand black dots in this application; SAM1 hides the text controls.

For Prompt project, whole image, the app builds candidate masks using grid prompts and positive exemplars (including selected existing objects), supplements small-object candidates using template-correlation seeds, pools SAM image embeddings through the predictor’s get_image_embedding() feature accessor when available, and compares appearance/shape descriptors with positive and negative examples. Filters remove unsuitable, protected, too-small, or duplicate proposals. This is an application retrieval heuristic; it is not native semantic concept propagation or a trained nanoparticle classifier.

SAM2/2.1: the text detection → mask pipeline#

With a text prompt, the app resolves aliases and sends the phrase/image to the pinned Grounding DINO Tiny detector. Its text-conditioned boxes are passed to the selected SAM2/2.1 predictor, which supplies the pixel masks. The app then applies region/protection/area/duplicate filtering and presents a preview.

Typed phrase → project alias resolution → Grounding DINO boxes
             → SAM2/2.1 masks → application filters → review → accept

The detector and SAM checkpoints are separate downloads. A box detection is not yet a particle mask. Prompts that work for photographs may transfer poorly to TEM/SEM. A threshold cannot repair a concept the detector does not locate. Point/shape whole-image exemplar search uses the application’s retrieval layer described above.

SAM3 ONNX: exported text inference#

The public export encodes uint8 RGB pixels and CLIP text, then decodes original-size masks and scores. It requires no HF authentication. Application filters, aliases, review/accept and exact ROI limits remain available. This export does not expose native point/shape concepts or automatic grids; choose native SAM3.1 for those. See the public ONNX workflow.

SAM3: native image concepts#

For native instance/ROI prompts, the processor computes image features and the parent model’s predict_inst shares them with its interactive predictor. Calling the interactive predictor’s independent set_image would fail because its tracker has no backbone; v1.4.3 corrects this route.

The app’s SAM3 processor sets an image, applies an optional native text prompt, and adds positive/negative geometric prompts. Shape/point exemplars first produce an instance mask whose bounding box becomes the concept example. The native image processor uses normalized center-X, center-Y, width, height boxes. This coordinate contract is different from the SAM3.1 adapter.

SAM3.1: native multiplex concepts on one frame#

The app loads sam3.1_multiplex.pt through build_sam3_multiplex_video_predictor, with compilation, FA3, and warm-up disabled. Each request creates a lossless PNG frame, starts a native session, sends a frame-0 add_prompt, copies masks/scores, and closes the session. This is a single-image adaptation, not a GUI video tracking workflow.

Text and/or positive/negative examples → one native SAM3.1 concept request
                                      → masks/scores → app filters → preview

All concept boxes are passed together in normalized top-left X, Y, width, height format. Area shapes become enclosing boxes; their exact contours are not sent as arbitrary polygon prompts. Each point exemplar first identifies a native instance, then its box describes the positive/negative concept. The SAM3.1 guide explains the visible workflow and its scope.

Automatic grid is a separate operation#

Automatic grid, unannotated only places native positive point prompts on a grid over unprotected pixels. It ignores the text field. The grid is not a second invocation of text detection and does not use the active text alias. The displayed count reports actual filtered proposals; zero is a result to inspect, not proof of a successful particle detector.

Review the outputs#

The model’s score is not a calibrated scientific probability. Check split/merged instances, faint particles, contamination, overlap, and image edges. Measure pixel and instance agreement against independently reviewed annotations for your own data. No new GPU benchmark or general microscopy accuracy claim is made by these descriptions.
